# DSH 工具与插件手记

内部速查整理而来，攒下来的都是「怎么做对」，不是「有哪些参数」。原稿是一份一万九千字的单文件，
现在按用途分成五册，为的是**按需取用**：人只下自己要看的那册，agent 一次只读一册，不用把全文塞进上下文。

> 这是 `manual/` 目录的索引。仓库根目录的 `README.md` 是另一份东西，未作改动。

## 分册

| 册 | 内容 | 体量 |
|---|---|---|
| [工具与运行时](01-tools-and-runtimes.md) | 在这台机器上把命令跑对：shell 版本差异、文件工具、Python 与 Node 解释器、几个现成脚本。 | 272 行 |
| [仓库与发布](02-github-and-release.md) | 往 GitHub 推东西：API 与 git 两条路怎么分、一次完整发布要走哪几步、出错时哪些动作是白费。 | 291 行 |
| [网络分诊](03-network-triage.md) | 连不上的时候按层查：代理层、TCP 层、传输层，各自的现象和处置不一样，先分层再动手。 | 102 行 |
| [调试与自检](04-debugging.md) | 东西不工作时怎么定位：探针放哪、分层问什么、写之前先过一遍什么。 | 110 行 |
| [插件接口层](05-plugin-interface.md) | 写 DSH 插件时容易踩空的地方：钩子返回什么、为什么会停在半路、版本范围怎么填、请求怎么发。 | 128 行 |

单册在 2000 到 6900 字符之间，原稿是 19,400。

## 你该读哪册

- 只想把命令在这台机器上跑对 → **第 1 册**
- 要往 GitHub 推东西，或者想弄清 API 与 git 的分工 → **第 2 册**
- 连不上，或者时通时不通 → **第 3 册**
- 装了没效果、卡住、查不出原因 → **第 4 册**
- 在写 DSH 插件 → **第 5 册**

拿不准先读第 4 册，它讲的是怎么定位，不假设你卡在哪一层。

## 给 agent 的说明

五册互相独立，可以只取一册。跨册引用只出现在第 2 册内部（引用第 3 册的分诊），其余各册自足。
需要整份的时候再全取，正常情况下不要一次读完。
